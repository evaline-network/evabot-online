# 🌐 EvaLine Platform Unification — Единая платформа из независимых узлов

**Версия:** 0.1.0 (концепт-план)
**Дата:** 6 сентября 2026 г.
**Автор:** EvaBot Engineering Team (аудит + архитектура)
**Статус:** План на согласование → реализация после ревью

---

## 1. Цель

Связать **все проекты и сервисы экосистемы EvaLine** в единую платформу с общей
навигацией, единым дизайн-стандартом и общим бэкендом, **при этом каждый узел
остаётся полностью независимым**: может жить, деплоиться и работать сам по себе,
а при падении других узлов не теряет работоспособность.

### 2.3 Сервисы на EvaFace

- **Caddy** — единственный владелец `:80` / `:443`, `default_sni evabot.online`.
- Обслуживает **4 домена** из `/var/www/<domain>/index.html`.

### 2.4 Четыре домена и их специализация

| Домен | Каталог (EvaFace) | Специализация | Размер index |
| :--- | :--- | :--- | :--- |
| `evabot.online` | `/var/www/evabot.online` | AI Neural Core (модели, Consilium, TUI-чат) | ~32 КБ |
| `evaline.network` | `/var/www/evaline.network` | Edge Mesh и сетевая топология | ~26 КБ |
| `evaline.online` | `/var/www/evaline.online` | Security, IAM, микросервисы | ~26 КБ |
| `evaline.website` | `/var/www/evaline.website` | Master Chronicle и Worklog | ~26 КБ |

Каждый домен в Caddy: `root * /var/www/<domain>` + `handle /api/*` → reverse_proxy `100.66.98.4:3000`.

### 2.5 Что уже связывает сайты

- Все домены вызывают общие API: `/api/chat`, `/api/health`, `/api/worklog`.
- Единый навигационный блок `EVALINE ECOSYSTEM MESH`.
- Единый бэкенд на Brain, проксируемый через Caddy по Tailscale.
- Worklog синхронизирован между узлами (TSV/LOG/TXT/MD).

## 3. Целевая архитектура: «Единая платформа = Mesh независимых узлов»

```
                        ┌──────────────────────────────────────────┐
                        │           CLIENT / BROWSER               │
                        └──────────────────┬───────────────────────┘
                                           │ HTTPS :443
                    ┌──────────────────────┼──────────────────────┐
                    ▼                      ▼                      ▼
             evabot.online          evaline.network        evaline.online
             evaline.website        (и др. будущие узлы)
                    │                      │                      │
                    └──────────┬───────────┴───────────┬──────────┘
                               ▼                       │
                 ┌─────────────────────┐               │
                 │  EvaFace (Caddy)    │               │
                 │  общий CDN/статик    │   /api/* по Tailscale
                 │  + общий bundle.js   │               │
                 └─────────┬───────────┘               │
                           ▼                           │
                 ┌─────────────────────┐               │
                 │  EvaBrain (Brain)   │◄──────────────┘
                 │  evabot-brain:3000  │
                 │  omniroute:20128    │
                 │  antigravity:9090   │
                 │  n8n:5678           │
                 └─────────────────────┘
```

### 3.1 Ключевой принцип

1. **Общий движок (bundle)** — единый JS-файл с терминальным TUI-движком,
   темой, навигацией, виджетами. Один раз собран, раздаётся как статика.
2. **Домен-специфичный конфиг** — маленький JSON/JS на каждый узел:
   `{ siteId, title, section, modules: [...], apiBase, theme }`.
   Узел выбирает и монтирует только нужные модули. **Сайт работает без остальных.**
3. **Общий backend** — один evabot-brain :3000 на Brain, проксируется на все домены.
   Устройства API описаны отдельно (см. п.5).
4. **Mesh-навигация** — общий компонент навигации, но каждая страница при недоступности
   остальных узлов показывает graceful fallback (оффлайн-статус), а не ломается.

## 5. Единый контракт API (общий backend на Brain)

Все домены общаются с `evabot-brain:3000` через относительные пути `/api/*`
(проксируется Caddy). Это **не требует** домен-специфичных ключей и упрощает независимость.

| Метод | Путь | Назначение |
| :--- | :--- | :--- |
| GET | `/api/health` | Статус бэкенда + кластера (Brain/Face/WireGuard) |
| GET | `/api/nodes` | Живой статус всех узлов платформы *(новое)* |
| POST | `/api/chat` | Унарная генерация чата |
| POST | `/api/chat/stream` | SSE-стриминг |
| POST | `/api/consilium` | Consilium (solo/broadcast/dialogue/consilium) |
| GET | `/api/models` | Каталог моделей (36 шт., USD/EUR) |
| GET | `/api/roles` | Корпоративные роли |
| GET | `/api/diagnostics/boot` | Диагностика загрузки |
| GET | `/api/worklog` | Хроника (JSON) |
| GET | `/api/openapi.json` | Спецификация API *(новое)* |

## 6. Принципы, гарантирующие независимость

1. **Статика отделена от данных.** Каждый HTML/JS работает без backend’а:
   метрики и навигация показывают "OFFLINE", но страница рендерится.
2. **Общий код — один источник истины; контент — локальный.** Домен может
   иметь собственную секцию/модуль, не влияя на другие.
3. **Проксирование `/api/*` опционально-глобально.** Caddy-блок вынесен в
   общий импорт; добавление нового домена — одна строка + одна папка.
4. **Mesh-навигация не является критическим путём.** Она просто информирует о
   доступности соседей, не блокируя работу текущего узла.

## 7. Риски и решения

| Риск | Решение |
| :--- | :--- |
| Дублирование кода в 4 HTML → рассинхрон | Единый `bundle.js` + конфиг узла |
| e2-micro не тянет много статики | CDN-логика: статика кэшируется, bundle один |
| Падение одной службы Brain | Graceful fallback, статусы в `/api/nodes` |
| Много доменов в Caddyfile → дублирование | Общий `import common_api` + `import common_root` |

## 8. Итог (что даст реализация)

- **Единая платформа:** общий дизайн, навигация, бэкенд, каталог моделей.
- **Независимые узлы:** каждый домен самодостаточен и работает при отказе остальных.
- **Минимум дублирования:** один bundle, один сервер, один конфиг-формат.
- **Масштабируемость:** новый домен = папка + конфиг + строка в Caddy.
