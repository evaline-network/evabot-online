## 4. Почему сайты и домены на микро-сервере казались неактивными

В ходе комплексной диагностики выявлены **4 ключевые технические причины**, из-за которых сайты казались неактивными или неработоспособными:

1. **Архитектурное разделение роли "Edge Ingress" и "Compute Core":**
   - На микро-сервере `evaline-micro-vm` сервис `evabot-chat.service` находился в статусе `inactive (dead)`. Это было сделано намеренно для защиты 1 GB памяти e2-micro от падения по OOM (Out Of Memory).
   - Все вызовы API (`/api/*`) прозрачно проксируются через Caddy на мощный вычислительный сервер `evabot-agent-vm` (`100.66.98.4:3000`). Но из-за отсутствия локального бэкенда при проверке через `systemctl` создавалось впечатление, что сервисы не запущены.

2. **Сбой внешнего DNS через Tailscale MagicDNS:**
   - Демон Tailscale перезаписал `/etc/resolv.conf` на адрес `100.100.100.100` / `fd7a:115c:a1e0::53`.
   - При внешних запросах MagicDNS возвращал ошибку `SERVFAIL` (`server misbehaving`). В логах Caddy фиксировались ошибки обновления сертификатов ACME Let's Encrypt (`failed updating renewal info`). Любые внешние вызовы с микросервера (включая curl, git pull и проверку сторонних адресов) зависали.
   - **Исправление:** Выполнена команда `tailscale set --accept-dns=false` и восстановлена корректная маршрутизация к резолверам Google/GCP Metadata (`169.254.169.254`).

3. **Отсутствие динамической телеметрии на 3 из 4 доменов:**
   - До этого дня частичный JavaScript-опрос метрик работал только на `evabot.online`.
   - На доменах `evaline.network`, `evaline.online` и `evaline.website` лежали статические макеты страниц без функции `pollHealth()`, с замороженными фиктивными числами и неработающими формами ввода, что вызывало ощущение "замерзших и мертвых" страниц.

4. **Статический текст в CLI fallback (`terminal.txt`):**
   - При обращении через консоль (`curl`) Caddy отдавал статический текстовый файл, в котором упоминался только один домен и не было живых метрик обоих серверов.

## 5. Выполненные работы: Унифицированные TUI-заглушки

Для всех 4 доменов разработаны и развернуты **одноименные терминальные текстовые заглушки в стиле строгого построчного CLI/TUI интерфейса**:

### 5.1. Реестр доменов и перекрестные ссылки

Каждая страница четко выделяет текущий узел и содержит структурированное описание всех узлов с прямыми ссылками:

- **`evabot.online`** — *AI Нейросетевое Ядро & Мульти-LLM Консилиум (Compute Core)*. Главный вычислительный узел кластера (Франкфурт, 8 vCPU, 32 GB RAM). Оркестрация моделей Gemini 3.8, Claude 3.5, DeepSeek V3.

- **`evaline.network`** — *Edge Mesh, Сетевая Маршрутизация & WireGuard Магистраль*. Транспортный контур (Айова, Caddy 2.11, HTTP/3 QUIC), шифрованный трансатлантический туннель США ↔ Германия.

- **`evaline.online`** — *Контур Периметровой Безопасности, IAM & Управление Демонами*. Изоляция бэкенда (WAN drop), защита от OOM, управление IAM и политиками доступа.

- **`evaline.website`** — *Мастер-Хроника, Архитектурный Аудит & Инженерный Worklog*. Единый журнал аудита (71+ этапов модернизации), спецификации, машиночитаемые логи TSV/LOG/JSON.

### 5.2. Реальные живые метрики обоих серверов (Dual-Server Telemetry)

На страницах выводятся реальные параметры аппаратуры и состояния:

- `evabot-agent-vm`: Реальный Load Average, загрузка CPU в %, используемая и общая RAM DDR5, количество моделей онлайн (78 моделей).

- `evaline-micro-vm`: Параметры 2 vCPU AMD EPYC, 1 GB RAM + 2 GB Swap, веб-сервер Caddy 2.11 HTTP/3.

- Туннель WireGuard: Задержка ~104 ms RTT, шифр ChaCha20-Poly1305, 0% потерь.

### 5.3. Анимированные элементы и построчный терминальный интерфейс

- **Пульсирующий светодиод:** Зеленый индикатор `● LIVE` с эффектом пульсации неонового свечения.

- **Анимированный курсор:** Мигающий блок терминала `█` в строке `evabot@evaline-mesh:~$`.

- **ASCII-спиннер:** Живой индикатор сетевой активности `⠋ ⠙ ⠹ ⠸ ⠼ ⠴ ⠦ ⠧ ⠇ ⠏`.

- **Динамические ASCII-шкалы:** Заполнение `[■■■■□□□□□□]` синхронно с реальным процентом нагрузки CPU и RAM.

- **Фоновый опрос:** Каждые 3.5 секунды страница опрашивает `/api/health` и плавно обновляет метрики без перезагрузки страницы.

- **Интерактивные терминальные команды:** Кнопки `[ ⚡ PROBE /api/health ]` и `[ 📋 ПОКАЗАТЬ RAW JSON ]` для мгновенной проверки ответа ядра прямо в консоли страницы.

- **CLI-поддержка (curl):** Для пользователей терминала отдается лаконичный текстовый файл `terminal.txt` со спецификацией узлов и командами проверки.
